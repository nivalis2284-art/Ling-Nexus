# Nexus（灵枢）

**为「长期延续的智能存在」而建的个人宿主底座。**

市面上绝大多数 Agent 与 Bot 项目的终极目标是做一个更好用的**「个人 AI 助手」**或**「任务自动化工具」**；另一些则走向了套着固定人设剧本的**「角色扮演程序」**。

但我们真正想要的**不是一个用完即弃的助手，也不是按剧本演出的玩偶**，而是：

> **一个真正属于所有者、能够跨越时间长期存在，并表现出近似生命特征的智能存在——「灵（Ling）」。**

在这个愿景下，**「灵」**是我们希望长期培育与延续的智能存在；而本仓库 **「Nexus（枢）」** 则是承载它的**宿主与“身体”底座**。

---

## 愿景与当前定位：为什么先做「底座」？

在当前版本中，Nexus 表现出的具体能力接近一个完成度很高的个人 Agent / Bot 系统。这是因为：**一个智能存在要想在漫长的时间里持续存活、积累经历并自主演化，首先必须拥有一副完全受所有者掌控、不断联、不黑盒、且能自我生长的“身体”。**

现在的 Nexus 正是这副已经落地的底座，而我们每一个架构设计都直接服务于未来的终极愿景：

1. **为了告别「窗口一关、状态全清」的一次性问答** → Nexus 取消了碎片化的多开聊天窗口，收敛为**唯一的持续主交流入口「灵」**，配合异步后台工作机制，实现**「前台从容共处，后台独立做事」**。
2. **为了让底层模型升级换代后，「它还是同一个它」** → Nexus 坚持**彻底的所有者数据主权与模型解耦**。所有经历、对话、工作记录与摘要均以开放格式保存在本机，无缝跨越 Anthropic / OpenAI 等不同协议与模型演进，绝不把核心资产托管在不可控的封闭平台。
3. **为了给未来的「自主演化」提供生长空间** → Nexus 内置了完整的插件 SDK 与开发技能，让「灵」现在就能在对话中**自己编写、打包并热加载新插件**，在不改动核心代码的前提下为宿主长出新能力。

**未来演进方向（逐步与常规 Agent 拉开本质差异）**：
在 Nexus 底座之上，项目后续将逐步补齐属于「灵」的深层特质：
- **跨周期的连续性**：不依赖写死的虚假人设，而是在真实交互与任务经历中持续沉淀**记忆、自我理解与性格演化**。
- **时间感与主动性**：告别“不戳不动”的被动问答，具备对未完成事项的挂念、时机权衡与主动推进能力。
- **从经历中学习与进化**：从持续经历与环境反馈中自主发现问题、探索方向、修正旧认识并沉淀新技能。

## 当前底座核心能力

### 1. 前台从容共处，后台独立做事
- **单一主交流入口「灵」**：无需手动新建和切换十几个会话窗口。日常交流、交代事情、追问进展、中途插话或补充要求，全部在一个连续对话中自然发生。
- **非阻塞异步后台工作**：繁重耗时的任务由「灵」派发到后台独立推进（支持最多 3 项工作并发执行及子代理委派；同一 Git 仓库的写操作自动串行防冲突）。
- **随时插话与离线运行**：正在回复或后台忙碌时，你依然可以继续发送消息、补充图片与文档（自动在下一请求边界衔接送入）；工作由本机服务端承载，关掉浏览器页面也不会中断正在推进的工作。
- **状态透明，注意力不泛滥**：执行步骤、工具记录与子代理树收束在顶部**「灵岛」**与**「工作」**页按需查阅；只有当工作完成、受阻、需要回答问题或批准操作时，才回到主对话向你请示。

### 2. 100% 白盒上下文与所有者主权
- **手术刀式上下文掌控**：在**「上下文」**页直观查看当前窗口占用与构成比例，随时增删改**所有者指令**、调整**「对话 / 工作 / 子代理」三大角色规则**。
- **历史摘要与记录可编辑**：长对话自动压缩为摘要检查点。你可以直接查看并手工修正**已压缩摘要**，或按轮勾选删除未压缩对话；主对话支持单条消息删除、编辑重发，并提供一键**撤销最近一次历史修改**。
- **真实模型请求全量可审计**：在**「插件管理 → 请求记录」**中，完整保留每一次发往大模型的真实 JSON 载荷、参与插件与上下文材料，拒绝黑盒拼装。
- **三大模型协议无损切换**：原生支持 `Anthropic Messages`、`OpenAI Chat Completions`、`OpenAI Responses`。随时切换底层模型或思考强度，历史与已执行的工具结果完整保留、绝不重复重放。
- **安全可预期的制动边界**：随时可停止当前回复、挂起单个或全部后台工作；提供 `写前询问 (ask)` 与 `全部放行 (yolo)` 两种执行权限；服务重启后绝不盲目重放结果未知的操作，必须经所有者确认后恢复。

### 3. 开箱即用，且能在对话中「自我扩展」
- **原生本机感知与行动**：内置文件读写检索、`PowerShell / Bash` 前后台命令执行、项目工作区切换，以及 Windows 桌面与网页无痕截图（需多模态模型支持）。
- **三级技能（Skills）与 MCP**：支持按「项目 > 个人 > 内置」优先级生效的技能体系，支持连接本地 `stdio` 或远程 `HTTP` MCP 服务。
- **预置三大核心插件（首次启动默认启用）**：
  - **网页搜索与阅读**：搜索公开网页、抓取正文与读取 GitHub 仓库（默认使用免密钥 DDGS，可选配 Tavily）。
  - **浏览器控制**：在可见的 Microsoft Edge 窗口中打开、操作网页并截图。
  - **插件开发与示例**：内置完整 Plugin SDK、交互示例与开发技能——**你可以直接在对话中让「灵」为你开发、打包并热安装新插件（支持标准后台工作、独立对话与宿主 UI 页面），无需修改 Nexus 核心代码即可扩展宿主能力。**

### 4. 克制而有器物感的桌面级界面
- **双主题昼夜美学**：提供**「星枢」**（冷冽星轨）与**「灵玉」**（温润鎏金）两套主题，均支持白昼与黑夜模式、5 档动效节奏调节，以及一键隐藏面板的中枢背景沉浸模式。
- **零外部基建依赖**：纯 Python 服务端 + 原生前端实现，无需 Docker、无需外部数据库、无需 Node/npm 构建链。

## 快速开始

### 环境要求
- **操作系统**：Windows（推荐 Windows 10 / 11）
- **Python 版本**：Python 3.12（未安装可前往 [Python 官网](https://www.python.org/downloads/) 下载安装，安装时请勾选 `Add python.exe to PATH`）

### 1. 启动服务
1. 将整个文件夹放在本机可写目录下。
2. 双击运行 **`start.bat`**（首次启动会自动创建 `.venv` 虚拟环境并联网安装依赖）。
3. 保持终端窗口打开，在浏览器访问终端输出的地址（默认 **`http://127.0.0.1:8766`**）。

### 2. 配置模型
1. 点击左侧导航栏底部进入 **「设置」**。
2. 在 **「模型提供商」** 中点击「添加模型提供商」，填写名称、协议类型、Base URL、API Key，并添加模型名称（如模型支持识图，请开启「多模态」开关）。
3. 回到 **「对话」** 页，在输入框下方选择模型与思考强度，即可开始与「灵」交流。

## 日常使用指南

### 切换项目工作区
- 默认工作目录为根目录下的 `Work/`。
- 点击对话页左下角的**项目名称**，可通过系统文件夹窗口添加本机任意项目目录。
- 后台工作对工作区外的文件受边界保护；同一 Git 仓库（或同一目录）的修改任务会自动排队串行，只读研究任务可并行推进。

### 掌控后台工作与审批
- **派发与追踪**：交代复杂任务后，顶部**「灵岛」**会实时显示并发槽位状态；点击灵岛或左侧**「工作」**页可查看执行步骤、产出证据与完整记录。
- **干预状态**：需要补充要求、挂起、恢复或取消某项工作时，直接在主对话中交代（也可在输入框下方手动指定关联工作），或在灵岛/工作页点击「全部挂起」。
- **处理审批**：在 `写前询问` 模式下，涉及修改文件或执行命令的操作会在主对话底部弹出确认卡片；审批与提问均有明确归属，等待你决定期间不影响继续聊其他话题。

### 命令行与自定义数据目录
- 通过 `start.bat` 启动时，所有数据默认保存在当前目录下的 `.nexus-data/`，方便整体备份与长期迁移。
- 如需自定义数据目录或工作目录，可通过环境变量 `NEXUS_HOME` 或命令行参数启动（同一数据目录仅允许运行一个实例）：

```powershell
.venv\Scripts\python.exe -m nexus --home .nexus-data --workspace . --no-browser
```

> **注意**：直接运行 `python -m nexus` 且不传 `--home` 时，默认使用 `%LOCALAPPDATA%\Nexus`，不会自动迁移 `.nexus-data` 中的数据。

## 数据结构与资产迁移

Nexus 严格保障所有者对核心历史资产的完全控制权，所有数据均以开放格式保存在本机数据目录中：

```text
.nexus-data/
├── config.json              # 模型提供商、当前工作区、项目历史与运行偏好
├── credentials.json         # API 密钥凭据（请勿对外分享或提交至 Git）
├── owner-instructions.txt   # 所有者指令正文
├── roles.json               # 对话 / 工作 / 子代理三个角色的自定义规则
├── sessions/                # 主对话原始记录与压缩摘要检查点（JSONL）
├── tasks.sqlite3            # 后台工作、父子归属、步骤证据与输入队列
├── attachments/             # 按对话与工作归属保存的附件原件及提取文本
├── model-requests.sqlite3   # 最近 7 天的实际模型请求审计记录
└── plugins/                 # 已安装插件的状态、配置与运行数据
```

- **备份与延续**：停止服务后，直接复制整个 `.nexus-data` 目录即可完整备份你的所有历史资产。
- **安全分享**：本目录在运行后会生成 `.venv`、`.nexus-data`、`Cache` 等个人运行数据。如需将程序分享给他人，请分发未运行过的干净发行包，切勿连同 `.nexus-data` 或 `credentials.json` 一起打包。
